*********************************** Обработка запросов в традиционных и MPP СУБД ***********************************

Жизненный цикл запроса:
Клиенты -> Парсер -> Оптимизатор -> Исполнитель
Клиенты -> GP master(MPP GreenPlum) -> QD query Dispatcher -> Query Executor

--------------------------------------------------------------------------------------------------------------------

Ресурсы:
 - CPU -> L1, L2 Cache
 - RAM  -> Process Memory
        -> Shared Buffer
        -> Disck Cache
 - Storage
 - Network(Только GP)

--------------------------------------------------------------------------------------------------------------------

Как оптимизатор принимает решение (Cost Based Optimizer):
 - Словарь данных -> Размер объекта, тип хранения, есть ли индексы
 - Статистика -> Селективность, гистограмма, оценка размеров резалтсет

Создание множество вариантов + расчет стоимости

--------------------------------------------------------------------------------------------------------------------

Как выполняется план:
Limit -> Sort -> Hash Join -> Hash -> Seq Scan
Seq Scan -> Hash -> Hash Join -> Sort -> Limit

--------------------------------------------------------------------------------------------------------------------

Узлы плана:
 - Sequential Scan
 - Index Scan
 - Index Only Scan
 - Bitmap Scan
 - Nested Loop Join
 - Hash Join
 - Merge Join
 - Sort
 - Aggregate
 - Group by Aggregate
 - Limit

Дополнительные Операторы плана GP:
 - Redistribute Motion
 - Gather Motion
 - External Scan

 Как повлиять на план:
  - Hints(не наш случай)
  - Параметры оптимизатора
  - Переписать запрос
